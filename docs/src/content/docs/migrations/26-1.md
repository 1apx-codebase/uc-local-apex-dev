Use this guide to migrate from UC Local APEX Dev 25.3 to 26.1. This release moves from a 23ai database container to a 26ai database container.

If you are installing for the first time, use [Getting Started](/products/uc-local-apex-dev/docs/getting-started/) instead.

## Changes

This section lists the main changes.

| Name | Description |
| --- | --- |
| Oracle Database | Moves from 23ai to 26ai, shown by the database image version `23.26.0`. |
| Datafiles | Not compatible. You must export from 23ai and import into 26ai. |
| ORDS | Upgrades from `25.2` to `25.4`. |
| `import-all.sh` | Imports all files from `./backups/import`. |
| `unexpire-accounts.sh` | Unlocks APEX public and workspace accounts after migration. |
| `fix-ws-group-ids.sh` | Removes APEX workspace group assignment IDs that can break imports. |
| `disable-password-expiration.sh` | Disables APEX workspace password expiration for local development. |
| Backup and import scripts | Add ORDS export support, remap schema support, and `-y` automation flags. |
| `create-user.sh` | Adds user name validation and improved quoting. |

## Before You Begin

This section confirms that you are ready to migrate.

> **Important**
> Start from release 25.3. If you are on an older release, run the earlier migrations first.

> **Caution**
> The 23ai and 26ai datafiles are not compatible. You must export data from the old database and import it into the new database.

> **Caution**
> `backup-all` backs up schemas, APEX workspaces, APEX applications, and ORDS modules for users created with this project's `create-user` command. Back up any other schemas, workspaces, or artifacts manually.

1. Pull the latest 25.3 changes.

   ```bash
   git fetch
   git pull origin 25-3
   ```

2. Make the scripts executable.

   ```bash
   chmod +x ./local-23ai.sh ./setup.sh ./scripts/*.sh
   ```

3. Confirm that the 23ai database is running.

   ```bash
   docker ps
   ```

4. If the database is not running, start it.

   ```bash
   local-23ai.sh start
   ```

## Back Up the 23ai Environment

This section exports the old database data and keeps a copy of the old project folder.

1. Back up all users created by this project.

   ```bash
   local-23ai.sh backup-all
   ```

2. Confirm that backup files exist in `backups/export`.

3. Back up any schemas or workspaces that were not created by this project.

4. Back up the `oradata` volume.

   > **Important**
   > Make sure `./backups/oradata` does not already exist before you copy the volume.

   ```bash
   source ./scripts/util/load_env.sh

   docker exec $CONTAINER_NAME bash -c "echo 'shutdown immediate;
   exit' | sqlplus / as sysdba && exit"

   docker cp $CONTAINER_NAME:/opt/oracle/oradata ./backups/oradata
   ```

5. Copy the whole project folder.

   ```bash
   cd ..
   cp -r uc-local-apex-dev uc-local-apex-dev-23ai
   cd uc-local-apex-dev
   ```

6. Stop the 23ai containers.

   ```bash
   local-23ai.sh stop
   ```

## Switch to 26ai

This section changes the project files and local configuration for 26ai.

1. Switch to the `26-1` branch.

   ```bash
   git fetch
   git checkout 26-1
   ```

2. Make the scripts executable.

   ```bash
   chmod +x ./local-26ai.sh ./setup.sh ./scripts/*.sh
   ```

3. Recreate the ORDS connection string.

   ```bash
   source ./scripts/util/load_env.sh
   echo "CONN_STRING=sys/$ORACLE_PASSWORD@26ai:1521/FREEPDB1" >./ords-secrets/conn_string.txt
   ```

4. Update `.env` on macOS.

   ```bash
   sed -i '' 's/DBHOST="23ai"/DBHOST="26ai"/' .env
   sed -i '' 's/CONTAINER_NAME=local-23ai/CONTAINER_NAME=local-26ai/' .env
   ```

5. On Linux, use these commands instead.

   ```bash
   sed -i 's/DBHOST="23ai"/DBHOST="26ai"/' .env
   sed -i 's/CONTAINER_NAME=local-23ai/CONTAINER_NAME=local-26ai/' .env
   ```

6. Copy exports into the import folder.

   ```bash
   cp -r ./backups/export/ ./backups/import/
   ```

## Start and Prepare 26ai

This section starts the new containers and prepares APEX.

1. Start the 26ai containers.

   ```bash
   local-26ai.sh start
   ```

2. Watch the logs until the database and ORDS are ready.

   ```bash
   docker-compose logs --follow
   ```

3. Open [http://localhost:8181/ords](http://localhost:8181/ords) or [https://localhost:8443/ords](https://localhost:8443/ords).

   At this point, ORDS should load. APEX may not be ready yet.

4. Run the first-start setup script.

   ```bash
   ./scripts/after-first-db-start.sh
   ```

5. Restart the containers.

   ```bash
   local-26ai.sh stop
   local-26ai.sh start
   ```

6. Confirm that ORDS now shows APEX.

7. Unlock expired accounts.

   ```bash
   ./scripts/unexpire-accounts.sh
   ```

8. Optionally disable future APEX workspace password expiration.

   ```bash
   ./scripts/disable-password-expiration.sh
   ```

   APEX may still ask for a password change on first login after migration.

## Import Data

This section fixes known workspace export issues and imports the backups.

1. Fix APEX workspace group IDs in the import files.

   ```bash
   ./scripts/fix-ws-group-ids.sh
   ```

   This script changes `p_group_ids` values to empty strings in workspace export files. This avoids a known APEX workspace import issue with group assignments.

2. Import all files from `./backups/import`.

   ```bash
   ./scripts/import-all.sh > import-log.txt
   ```

3. Review the import summary.

4. If the summary shows failures, open `import-log.txt` and fix the reported errors.

## Verify

This section confirms that the migrated environment works.

1. Test SQLcl and VS Code SQL Developer connections.
2. Check that schema data exists.
3. Sign in to APEX workspaces.
4. Check that APEX applications exist.
5. Check that ORDS modules exist.

## Remove the Old 23ai Environment

This section removes the old 23ai folder, containers, volume, and images after you verify the 26ai environment.

> **Caution**
> Do not remove the old environment until you have verified the 26ai import and have backups you trust.

1. Delete the backup project folder if you no longer need it.

   ```bash
   rm -r ../uc-local-apex-dev-23ai
   ```

2. Remove the old containers.

   ```bash
   docker rm local-23ai local-ords
   ```

3. Remove the old volume.

   ```bash
   docker volume rm oradata
   ```

4. Optionally list and remove old images.

   ```bash
   docker image ls
   docker image rm {image_name}
   ```
