Use this guide to migrate from UC Local APEX Dev 26.2 to 26.3. This release upgrades Oracle Database and ORDS in place and adds a one-command installer for fresh installs.

If you are installing for the first time, use [Getting Started](/products/uc-local-apex-dev/docs/getting-started/) instead.

## Changes

This section lists the main changes.

| Name | Description |
| --- | --- |
| Oracle Database | Upgrades from `23.26.1.0` to `23.26.2.0`. Datafiles are compatible. |
| ORDS | Upgrades from `26.1.0` to `26.1.2`. |
| `install.sh` | Adds a one-command installer for fresh installs. |
| `upgrade-apex.sh` | Adds a dedicated script for APEX upgrades. |
| `after-first-db-start.sh` | Adds command pre-checks and reuses `ORACLE_PASSWORD` for the APEX Internal `ADMIN` password. |
| APEX download | Works with `curl` or `wget`. |
| SQLcl scripts | Use a dumb terminal for non-interactive runs over SSH and in continuous integration. |
| Compose support | Prefers `docker compose` over standalone `docker-compose` when both are installed. |
| User removal | No longer errors when the user has no APEX workspace. |
| Testing | Adds workflows for clean installs and in-place database upgrades. |
| Documentation | Expands Windows setup instructions and fixes documentation issues. |

## Before You Begin

This section confirms that you are ready to migrate.

> **Important**
> Start from release 26.2. If you are on an older release, run the earlier migrations first.

> **Caution**
> Back up your database before you upgrade. If you created schemas or workspaces outside this project, back them up manually.

1. Confirm that the database is running.

   ```bash
   docker ps
   ```

2. If the database is not running, start it.

   ```bash
   ./local-26ai.sh start
   ```

## Migrate

This section upgrades the project files and starts the updated containers.

1. Back up schemas and APEX workspaces created by this project.

   ```bash
   ./local-26ai.sh backup-all
   ```

2. Confirm that backup files exist in `backups/export`.

3. Stop the containers.

   ```bash
   ./local-26ai.sh stop
   ```

4. Switch to the `26-3` branch.

   ```bash
   git fetch
   git checkout 26-3
   ```

5. Make all scripts executable.

   ```bash
   chmod +x ./local-26ai.sh ./setup.sh ./scripts/*.sh
   ```

6. Start the containers.

   ```bash
   ./local-26ai.sh start
   ```

7. Watch the database logs until you see `DATABASE IS READY TO USE!`.

   ```bash
   docker logs -f local-26ai
   ```

8. Watch the ORDS logs until ORDS reports that it is initialized.

   ```bash
   docker logs -f local-26ai-ords
   ```

## Verify

This section confirms that APEX is available after the migration.

1. Open [http://localhost:8181/ords/apex](http://localhost:8181/ords/apex).
2. Confirm that the APEX sign-in page loads.
3. Sign in to a workspace and check your application data.

After a major restart, some application objects may temporarily show as `INVALID`. Oracle can recompile them automatically on first use. To recompile them manually, connect as SYS and run:

```sql
begin
  sys.utl_recomp.recomp_serial();
end;
/
```

## Clean Up

This section removes old local images if you no longer need them.

1. Remove the old database image if you no longer need it.

   ```bash
   docker image rm container-registry.oracle.com/database/free:23.26.1.0
   ```

2. Remove the old ORDS image if you no longer need it.

   ```bash
   docker image rm container-registry.oracle.com/database/ords:26.1.0
   ```
