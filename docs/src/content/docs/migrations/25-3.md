Use this guide to migrate from UC Local APEX Dev 25.2 to 25.3. This release upgrades Oracle Database and moves from the deprecated `ords-developer` image to the `ords` image.

If you are installing for the first time, use [Getting Started](/products/uc-local-apex-dev/docs/getting-started/) instead.

## Changes

This section lists the main changes.

| Name | Description |
| --- | --- |
| Oracle Database | Upgrades from `23.7` to `23.8`. Datafiles are compatible. |
| ORDS | Upgrades from `ORDS Developer 24.4` to `ORDS 25.2`. |
| `test-script-install` | Tests SQL scripts in a clean environment. |
| `used-space` | Shows database storage usage. |
| `shrink-space` | Reclaims unused tablespace space. |

## Before You Begin

This section confirms that you are ready to migrate.

> **Important**
> Start from release 25.2. If you are on an older release, run the earlier migrations first.

> **Caution**
> Back up your database before you upgrade. If you created schemas or workspaces outside this project, back them up manually.

1. Confirm that the database is running.

   ```bash
   docker ps
   ```

2. If the database is not running, start it.

   ```bash
   local-23ai.sh start
   ```

## Migrate

This section upgrades the project and moves the APEX images for the new ORDS image.

1. Back up schemas and APEX workspaces created by this project.

   ```bash
   local-23ai.sh backup-all
   ```

2. Confirm that backup files exist in `backups/export`.

3. Optionally back up the `oradata` volume.

   > **Important**
   > Make sure `./backups/oradata` does not already exist before you copy the volume.

   ```bash
   source ./scripts/util/load_env.sh

   docker exec $CONTAINER_NAME bash -c "echo 'shutdown immediate;
   exit' | sqlplus / as sysdba && exit"

   docker cp $CONTAINER_NAME:/opt/oracle/oradata ./backups/oradata
   ```

4. Copy the APEX images out of the old ORDS container.

   ```bash
   docker cp local-ords:/opt/oracle/apex/24.1.0/images .
   mv images apex-images
   ```

5. Remove old ORDS files.

   ```bash
   rm .env.ords
   rm -r ords-secrets
   ```

6. Add ORDS environment variables to `.env`.

   ```bash
   echo "DBSERVICENAME=\"FREEPDB1\"" >>.env
   echo "DBHOST=\"23ai\"" >>.env
   echo "DBPORT=\"1521\"" >>.env
   echo "FORCE_SECURE=\"false\"" >>.env
   ```

7. Stop the containers.

   ```bash
   local-23ai.sh stop
   ```

8. Switch to the `25-3` branch.

   ```bash
   git fetch
   git checkout 25-3
   ```

9. Make the scripts executable.

   ```bash
   chmod +x ./local-23ai.sh ./setup.sh ./scripts/*.sh
   ```

10. Start the containers.

    ```bash
    local-23ai.sh start
    ```

11. Disable APEX password expiration.

    Connect as SYS with `sql -name local-23ai-sys`, then run:

    ```sql
    declare
      l_username varchar2(100);
    begin
      select creator
        into l_username
        from PUBLICSYN where SNAME = 'APEX_UTIL'
       fetch first 1 row only;

      execute IMMEDIATE ' update ' || l_username || q'!.wwv_flow_platform_prefs
            set VALUE = 10000
          where NAME = 'ACCOUNT_LIFETIME_DAYS'
      !';
      commit;
    end;
    /
    ```

## HTTPS Change

This section explains the ORDS URL change for HTTPS users.

> **Important**
> If you use HTTPS, open ORDS at `https://localhost:8443/ords`.

## Hotfix for DEBUG

This section documents a correction to an earlier version of this migration guide.

> **Caution**
> If your `.env` file contains `DEBUG=TRUE`, remove that line. SQLcl also uses `DEBUG`, and it can change script output.

If `.env` does not contain `DEBUG=TRUE`, no action is needed.

## Clean Up

This section removes old local images if you no longer need them.

1. List Docker images.

   ```bash
   docker image ls
   ```

2. Remove only images that you are sure you no longer need.

   ```bash
   docker image rm {image_name}
   ```
