Use this guide to install UC Local APEX Dev and start the local containers. When you finish, you can open Oracle APEX in your browser and connect to the database.

Oracle APEX is the application development platform. ORDS, or Oracle REST Data Services, is the web service that serves APEX and REST endpoints.

## Prerequisites

This section lists the software and resources you need before you install the environment.

| Name | Description | Required |
| --- | --- | --- |
| Docker or Podman | Container runtime used to run Oracle Database and ORDS. | Yes |
| Compose | `docker compose`, `docker-compose`, or `podman compose`. | Yes |
| SQLcl | Oracle command-line SQL tool. The `sql` command must be in your `PATH`. | Yes |
| Bash-compatible shell | Shell used to run the install and helper scripts. | Yes |
| `unzip` | Command used during setup. | Yes |
| `curl` or `wget` | Command used to download files during setup. | Yes |

<Aside type="caution" title="Resource requirements">
  Allocate enough resources to your container virtual machine. The default
  Podman virtual machine settings may be too small for Oracle Database.

  Recommended minimum: 4 GB RAM, 3 CPUs, and 20 GB disk space.
</Aside>

### Platform Notes

This section gives extra setup notes for specific operating systems.

| Name | Description |
| --- | --- |
| macOS | If you use Podman, read [Podman on macOS](/products/uc-local-apex-dev/docs/other/podman-on-mac/) before you install. |
| Windows | Use Windows Subsystem for Linux 2 (WSL2). Install Ubuntu, Docker inside Ubuntu, and SQLcl inside Ubuntu. |
| Linux | Install Docker or Podman, a compose command, SQLcl, and a Bash-compatible shell. |

<Aside type="note" title="Choose Docker or Podman">
  The scripts auto-detect the container runtime. If Docker and Podman are both
  installed, the scripts use Docker by default. To force Podman, run:

  ```bash
  CONTAINER_CLI=podman ./install.sh
  ```
</Aside>

## Install the Environment

This section installs the project, creates local configuration, pulls container images, starts the containers, and configures APEX.

1. Clone the repository.

   ```bash
   git clone https://github.com/United-Codes/uc-local-apex-dev.git
   cd uc-local-apex-dev
   ```

2. Make the scripts executable.

   ```bash
   chmod +x ./install.sh ./local-26ai.sh ./setup.sh ./scripts/*.sh
   ```

3. Run the installer.

   ```bash
   ./install.sh
   ```

4. Wait for the installer to finish.

   The install usually takes about 15 to 20 minutes. Most of the time is spent waiting for Oracle Database and ORDS to start.

The installer performs these actions:

| Name | Description |
| --- | --- |
| Dependency check | Checks for a container runtime, compose command, `sql`, `unzip`, and `curl` or `wget`. |
| Local configuration | Runs `./setup.sh` to create `.env` if needed. |
| Container images | Pulls the database and ORDS images. |
| Container startup | Starts the stack with the detected compose command. |
| Readiness wait | Waits for Oracle Database and ORDS to finish first startup. |
| ORDS gateway mode | Sets the ORDS PL/SQL gateway mode to `proxied`, which APEX uses. |
| APEX setup | Runs `./scripts/after-first-db-start.sh` to install APEX and apply local development settings. |
| ORDS restart | Restarts ORDS so it loads the APEX configuration. |

<Aside type="note" title="Existing .env file">
  If `.env` already exists and contains the required values, `setup.sh` keeps
  those values.
</Aside>

## Open APEX

This section verifies that APEX is available in your browser.

1. Open [http://localhost:8181/ords/apex](http://localhost:8181/ords/apex).
2. Sign in to the `INTERNAL` workspace.
3. Use `ADMIN` as the user name.
4. Use the `ORACLE_PASSWORD` value from `.env` as the password.

If APEX shows `Account Is Locked`, run:

```bash
./scripts/unexpire-accounts.sh
```

If APEX asks you to change passwords and you want to disable password expiration for local development, run:

```bash
./scripts/disable-password-expiration.sh
```

<Aside type="caution" title="Important: Local passwords">
  The `.env` file contains generated passwords. Keep it private, even for local
  development.
</Aside>

## Add the Project to Your Path

This section lets you run `local-26ai.sh` from any directory.

1. Open your shell startup file, such as `~/.zshrc` or `~/.bashrc`.
2. Add the repository path to `PATH`.

   ```bash
   export PATH="/Users/username/path/to/uc-local-apex-dev:$PATH"
   ```

3. Start a new terminal session.
4. Run a command from another directory.

   ```bash
   local-26ai.sh --help
   ```

## Access Details

This section lists the default URLs and connection values.

| Name | Description |
| --- | --- |
| APEX | [http://localhost:8181/ords/apex](http://localhost:8181/ords/apex) |
| ORDS landing page | [http://localhost:8181/ords/_/landing](http://localhost:8181/ords/_/landing) |
| Database host | `26ai` |
| Database port | `1521` |
| Database service | `FREEPDB1` |
| Internal APEX user | `ADMIN` |
| Internal APEX password | `ORACLE_PASSWORD` value from `.env` |
