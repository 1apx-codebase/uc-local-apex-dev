## Container Commands

This section shows how to start and stop the local containers.

| Name | Description |
| --- | --- |
| `local-26ai.sh start` | Starts the environment. |
| `local-26ai.sh stop` | Stops the environment cleanly. |
| `docker compose start` | Starts the containers with Docker Compose. |
| `docker compose stop` | Stops the containers with Docker Compose. |
| `podman compose start` | Starts the containers with Podman Compose. |
| `podman compose stop` | Stops the containers with Podman Compose. |

Use `local-26ai.sh stop` when possible. It stops the database cleanly.

## ORDS Configuration

This section explains how to change ORDS settings and enable local HTTPS.

ORDS, or Oracle REST Data Services, serves APEX pages and REST endpoints. Its configuration files are in `ords-config` after setup.

### Change ORDS Settings

1. Edit the files in `ords-config`.
2. Restart the ORDS container.

   ```bash
   docker compose restart ords-26ai
   ```

3. If you use Podman, run the Podman version instead.

   ```bash
   podman compose restart ords-26ai
   ```

### Enable Local HTTPS

This procedure creates self-signed certificates for local HTTPS. On macOS and Linux, the script also tries to add the certificate to the system trust store.

1. Run the certificate script.

   ```bash
   sudo ./scripts/create-self-signed-certificates.sh
   ```

2. Restart ORDS.

   ```bash
   docker compose restart ords-26ai
   ```

3. Open ORDS at [https://localhost:8443/ords](https://localhost:8443/ords).

<Aside type="note" title="HTTPS port">
  HTTPS uses port `8443`. HTTP uses port `8181`.
</Aside>

## Storage Maintenance

This section helps you monitor and reduce database disk usage.

Oracle Database Free has a storage limit. The `used-space` command shows how much of that limit you use.

### Check Database Space Usage

1. Run `used-space`.

   ```bash
   local-26ai.sh used-space
   ```

2. Review the database and tablespace output.

### Shrink Database Files

Use `shrink-space` when tablespaces have allocated more space than they currently use.

1. Run `shrink-space`.

   ```bash
   local-26ai.sh shrink-space
   ```

2. Wait for the script to finish. This can take a while.

### Compress a Schema Tablespace

Use `compress-space` to reduce the stored size of one schema. The command enables Oracle Advanced Compression on the schema tablespace and rebuilds existing objects.

| Name | Description |
| --- | --- |
| Tables | Uses advanced row compression, shown as `COMPRESS FOR OLTP`. |
| B-tree indexes | Uses advanced index compression, shown as `COMPRESS ADVANCED LOW`. |
| New objects | Inherit compression from the tablespace defaults. |

1. Run `compress-space` with the schema name.

   ```bash
   local-26ai.sh compress-space movies
   ```

2. Confirm the prompt.

To skip the confirmation prompt for automation, add `-y`.

```bash
local-26ai.sh compress-space movies -y
```

<Aside type="note" title="Compression behavior">
  The operation rebuilds objects and does not drop them. Already compressed
  objects are skipped. Single-column unique and primary-key indexes are left
  uncompressed because advanced index compression does not help them.
</Aside>

## APEX Account Maintenance

This section covers common APEX account expiration issues in a local environment.

### Unlock Expired Accounts

Run this command if `APEX_PUBLIC_USER` or workspace accounts are locked because passwords expired.

```bash
./scripts/unexpire-accounts.sh
```

### Disable Password Expiration

Run this command if you do not want APEX workspace accounts to expire.

```bash
./scripts/disable-password-expiration.sh
```

<Aside type="note" title="First login after migration">
  APEX may still ask users to change their password on first login after a
  migration.
</Aside>

## Workspace Import and Export

This section helps you import exported workspaces and fix a known import issue.

### Import All Export Files

Use `import-all.sh` to import files from `./backups/import`.

1. Copy the files you want to import into `./backups/import`.
2. Run the import script.

   ```bash
   ./scripts/import-all.sh
   ```

3. Review the success and failure summary.

### Fix Workspace Group IDs

Some APEX workspace exports can fail during import because of group assignment IDs. The fix script removes the group ID values from export files in `./backups/import`.

1. Copy the workspace export files into `./backups/import`.
2. Run the fix script.

   ```bash
   ./scripts/fix-ws-group-ids.sh
   ```

3. Run the import again.

## Reset the Environment

This section deletes all local database data and lets you start again from a clean environment.

<Aside type="caution" title="Permanent data loss">
  This reset deletes the container volume and `.env`. Back up anything you need
  before you run these commands.
</Aside>

1. Stop and remove the containers.

   ```bash
   docker compose down
   ```

2. Remove the database volume.

   ```bash
   docker volume rm oradata-26ai
   ```

3. Remove `.env`.

   ```bash
   rm .env
   ```

4. Follow [Getting Started](/products/uc-local-apex-dev/docs/getting-started/) again.

If you use Podman, replace `docker` with `podman`.
