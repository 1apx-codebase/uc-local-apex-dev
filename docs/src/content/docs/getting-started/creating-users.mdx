Use this guide to create and manage local database users. In this project, a database user owns a schema, and a schema contains database objects such as tables, views, packages, and indexes.

## Create a Schema and Workspace

This section creates one database schema and one matching APEX workspace.

1. Run `create-user` with the schema name you want.

   ```bash
   local-26ai.sh create-user movies
   ```

2. Wait for the script to finish.
3. Open APEX at [http://localhost:8181/ords/apex](http://localhost:8181/ords/apex).
4. Sign in with the workspace credentials shown in the following table.

| Name | Description |
| --- | --- |
| Workspace | Schema name, such as `MOVIES`. |
| User name | `ADMIN` or the schema name, such as `MOVIES`. |
| Password | Matching `<SCHEMA>_USER_PASSWORD` value in `.env`. |

The command performs these actions:

- Creates the schema.
- Stores the schema password in `.env`.
- Saves the connection in the SQLcl connection store.
- Adds development permissions for local work.
- Grants access to Data Pump directories.
- Creates an APEX workspace.
- Sets local development defaults for session length, email limits, REST message limits, and password lifetime.

## Create a Schema Without a Workspace

This section creates only a database schema. Use this when you do not need an APEX workspace.

1. Run `create-user` with `--skip-workspace`.

   ```bash
   local-26ai.sh create-user myschema --skip-workspace
   ```

2. Use the generated password from `.env` when you connect.

## Create a Compressed Schema

This section creates a schema whose new objects use Oracle Advanced Compression by default. Compression can reduce disk usage for tables and B-tree indexes.

1. Run `create-user` with `--compress`.

   ```bash
   local-26ai.sh create-user movies --compress
   ```

2. Add other options when needed.

   ```bash
   local-26ai.sh create-user myschema --skip-workspace --compress
   ```

<Aside type="note" title="Existing data">
  The `--compress` option sets defaults for new objects. To compress an
  existing schema, use `local-26ai.sh compress-space`. See
  [Compress a Schema Tablespace](/products/uc-local-apex-dev/docs/getting-started/common-tasks/#compress-a-schema-tablespace).
</Aside>

## Clear a Schema

This section removes objects from a schema but keeps the schema itself. Use it to test install scripts again in the same schema.

<Aside type="caution" title="Data loss">
  `clear-schema` drops all objects in the schema. Back up any data you need
  before you run it.
</Aside>

1. Run `clear-schema`.

   ```bash
   local-26ai.sh clear-schema movies
   ```

2. Confirm the prompt.

To skip the confirmation prompt for automation, add `-y`.

```bash
local-26ai.sh clear-schema movies -y
```

## Drop a Schema

This section permanently removes a schema, its objects, and its dedicated tablespace datafile.

<Aside type="caution" title="Permanent data loss">
  `drop-user` permanently removes the schema and reclaims its datafile. Back up
  any data you need before you run it.
</Aside>

1. Run `drop-user`.

   ```bash
   local-26ai.sh drop-user movies
   ```

2. Confirm the prompt.

To skip the confirmation prompt for automation, add `-y`.

```bash
local-26ai.sh drop-user movies -y
```

## Connect to the Database

This section shows how to connect to schemas created by the project.

All created users are saved in SQLcl's connection store.

| Name | Description |
| --- | --- |
| Schema user | `sql -name local-26ai-movies` |
| SYS user | `sql -name local-26ai-sys` |

The VS Code SQL Developer extension can also use these connections. Refresh the connection list if a new connection does not appear.

For other tools, use these values:

| Name | Description |
| --- | --- |
| Host | `26ai` |
| Port | `1521` |
| Service | `FREEPDB1` |
| User name | Your schema name. |
| Password | Matching password value from `.env`. |
